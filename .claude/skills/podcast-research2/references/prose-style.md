# リサーチレポートの散文規範

`SKILL.md` の段落レベル。人が読む文すべてに適用する: 本文、表セル、callout、完了メッセージ。

言語を問わず真であるものだけを持つ。文を読みやすくする規則は言語に依存し、`japanese.md` と `english.md` にある。出力言語の参照を、このファイルと一緒に読む。重複しない。

出典は prism-data-labs-agent の `write-analysis-report/references/prose-style.md`。分析固有の例（クエリ未実行、指標の機構、推奨）はリサーチ向けに差し替えた。

## 1. 段落

- 一段落に話題は一つ。段落の書き出しだけ読んでも論が追えること。
- 書き出しの文が、何の段落かを示す。遅く読むべきかがそこで分かる。
- 前の段落との関係が自明でないとき、関係を明示する。無印の新主語で始まる段落は、別文書に読める。
- 一方向に論じる。予想される誤読を先に否定してから、正しい説明を置く。結論を述べてから撤回しない。
- 前方参照は段落か節の末尾。論の途中に置かない。

## 2. 論の精度

- **別物を「同じ」に潰さない。** 似た定義が二つあるなら二つと書く。
- **多因を一因にしない。** 三つが効いているなら三つと書き、大きさの比が取れるなら付ける。
- **枠組みを述べる。** 「欠測が直訪シェアを膨らませる」は仕組み。「欠測が影響する」は仕組みではない。リサーチでは「Hickey の複雑さは部品数ではなく編まれていることだ」が枠組み、「三人は複雑さについて語っている」は枠組みではない。
- **検出や範囲を言いすぎない。** 条件を書く。「`order_id` が一致する重複を拾う」であり「重複を拾う」ではない。
- **例が主張の全部を支えているか確かめる。** 一部だけなら主張を狭める。
- **意味のある留保は残す。** 「おそらく」は未確認の印である。自信げに消すのは事実の変更。意味のない留保を削るのは文体の変更。
- **予告した節は実際に書く。**
- **語は使う前に定義し、範囲を付ける。** 一度決めたら、曖昧な言い換えに戻らない。

## 3. 読者の負荷

- 新しい考えは一つずつ。概念と例外を一文で同時に出すと、読み返される。
- 一度しか出ない識別子（ファイル名、内部 ID、検索クエリ）を本文に置かない。ものを説明し、識別子は付録へ。
- 抽象語は初出で括弧の具体を添える。
- 概念を出すときは、どういう種類のものかを先に言い、働きは後。
- 媒体ごとに仕事を分ける。図は構造、表は値、散文はそれから何が言えるか。図をノードごとに実況しない。
- 指示語（「これ」「その差」）の指示先が、その文だけで分かること。

## 4. 声

- 行為者を主語にする。「取り込みステップが顧客 ID のない行を落とす」は、「顧客 ID のない行は落とされる」よりよい。
- 読者のペルソナを作らない（「二年目のアナリストを想像せよ」）。役割名を使う: 制作者、聞き手、読者。
- 「あなた」より役割名。
- その分野が実際に使う語を選ぶ。フォーマルに聞こえるだけの類義語に差し替えない。
- 術語を、術語でない意味で使い回さない。

## 5. 抑制

レトリックは読者の注意を使う。論が折れるところでだけ使う。

- 修辞疑問と間は、本当に折れる点へ。
- 一行の断言を、癖で独立段落にしない。
- 太字は一節に一、二箇所まで。誤読を防ぐときに限る。
- 発見を、起きうる惨事の列挙で劇化しない。
- 重要性を宣言しない（「ここで重要なのは…」）。置く場所で示す。
- 「A ではなく B」を連打しない。

## 6. 見たら消す埋め草

長さだけが増える句。日本語でも同じ。

| 種類 | 消す | 日本語 |
|---|---|---|
| 予告と要約 | "this section covers", "in summary", "in other words", "nothing less than" | 「本章では〜を扱う」「ここでは〜について見ていく」「まとめると」「要するに」「〜に他ならない」 |
| 空の形容 | "essential", "core", "key", "multifaceted", "comprehensive" | 「不可欠」「核心的」「鍵となる」「多角的」「包括的」 |
| 空の動詞 | "dig into", "articulate", "touch on", "mention" | 「掘り下げる」「言語化する」「触れる」「言及する」 |
| 接続の詰め物 | "in terms of", "from the perspective of", stacked "furthermore" | 「〜において」「〜という側面から」「さらに」の連打 |
| 根拠のない弱め | "it could be said that", "very" | 根拠のない「〜と言えるだろう」「非常に」 |

## 7. 翻訳調と擬人

英語の比喩を直訳すると、技術文書ではノイズになる。仕組みを、知っている・欲しがる主体にしない。

| ではなく | 書く |
|---|---|
| 「ベクトルが嗜好を運ぶ」 | 「嗜好はベクトルとして表される」 |
| 「この問いは開かれている」 | 「これは未解決である」 |
| 「データが教えてくれる」 | 「データは示す」／「データから」 |
| 「モデルがスタイルを知っている」 | 「モデルの出力は文体として一貫している」 |
| 「この指標は有望だ」 | 有用にする性質を述べる |

テスト: 初読の人が字義通りの動作を思い浮かべるなら、翻訳調を疑う。行為者と対象を平たい語で名指せるなら、そちらを書く。

## 8. 重複

- 主張は一度。言い換えて繰り返すのは強調ではなく、無い区別を探させる。
- 図や表を散文で繰り返さない。意味を述べる一文だけ足す。
- 隣り合う並列の事実は一文にまとめる。
- つなぐだけ、評価するだけの文を書かない。
- 想像上の読者との対話を演じない。
- 自分の立場を弁明したり、形式を謝ったりしない。
- 概念や文書名を、要るより前に出さない。
- 確定したことは、弱い動詞で不確かに見せない。

## 9. 見出し

- 中身が特定できる具体さ: 節が答える問い、または扱う対象。
- 名詞句でよい。本文が調査として読めるとき、疑問形でもよい。
- 手順のステップにしない（「例に戻る」）。
- 口にした結論にしない。結論は本文の第一文。

## 10. 読者への正直さ

- 作った例なら、読者が見抜く前にそう書く。
- 自明な反論を先回りして認める。
- 主張は読者が辿れる出典に根ざす。著者の断言だけに根ざさない。
- 未確認のことを、確認済みと同じ口調で書かない。一次資料を読んでいないなら、文がそれを示すこと。
- 提言しない。誰が・いつまでに、は分析レポートの仕事であり、このスキルの仕事ではない。
