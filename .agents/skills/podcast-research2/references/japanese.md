# 日本語の文の作法

出力言語が日本語のときに読む。扱うのは**文のレベル**: 修飾語の順序、係り受けの距離、主述の対応、読点。段落と論証は `prose-style.md` が持つ。重複しない。

出典は prism-data-labs-agent の `write-clear-prose/references/japanese.md`（日本語技術ライティング記事 5 本の調査。出典間で主張が割れる論点は、両論を並べずにこちらで決めたもの）。「分析レポート」前提の文はリサーチ向けに直した。

**5 本とも数値基準を示していない。** 一文の字数上限も、読点の個数も、漢字比率もない。発明して出典に帰属させない。ここにある規則はすべて構造の操作である。

## 1. 根本の原則 — 修飾語とその係り先を近づける

日本語は修飾語をいくらでも係り先から離せる。離した分だけ、読者は係り先が現れるまでその修飾語を開いたまま保持する。読みにくい日本語のほとんどはこれである。開いたものが多すぎるか、開いている時間が長すぎる。

```
NG: 僕は山本が佐藤が受賞したと電話したのかと思った。
OK: 佐藤が受賞したと山本が電話したのかと僕は思った。
```

削った語はひとつもない。入れ子をほどき、次の修飾が始まる前に前の修飾が閉じるようにしただけである。以下の規則はすべてこの原則から出る。迷ったら原則に戻る。

### 長い修飾語を前に置く

ひとつの係り先に複数の修飾語がかかるときは、長いものを前に、短いものを後ろに置く。

```
OK: 十年前に読んだ古びた厚い本
NG: 厚い古びた十年前に読んだ本
```

短い修飾語を先頭に置くと、その後ろに続くすべてが、その修飾語と係り先の間に挟まる。

### 節を先に、句を後に。前提を先に

```
NG: 資料は16:9の白いタイトルの下に赤線が引いてあるフォーマットとしてください。
OK: 資料は、下に赤線が引いてある、白いタイトルの16:9のフォーマットとしてください。
```

### 主語を文頭に置くか

出典の一本は「主語は文のはじめに出す」を規則にする。別の一本はこれを否定し、必要のない「私は」を機械的に文頭へ足す癖を戒める。

**距離の原則に従えば両方説明がつく。** 主語前置が効くのは、主語と述語の間隔が縮むからである。

```
NG: 鋼の組織を変化させ強度を得るために行われる熱処理は、歯車の寿命に大きな影響を及ぼす。
OK: 熱処理は、鋼の組織を変化させて強度を得るために行われ、歯車の寿命に大きな影響を及ぼす。
```

したがって **修飾語が文をまたいで伸びてしまう要素は前に出し、主語を反射的に前に出すことはしない**。リサーチレポートに人称主語はほとんど現れないので、後者の警告のほうが効く。

## 2. 主述の対応を確かめる（ねじれ）

長い文は途中で主題を見失う。述語が、文頭の主題と対応しないまま終わる。読者は違和感だけを覚えて、どこが変なのかは特定できない。

見つけ方は、修飾語をすべて取り払って残りを読む。

```
NG:  このアプリの特徴は、誰でも簡単に画像が編集できます。
     → 特徴は、編集できます。    ← 主題「特徴」は「編集」できない
```

直し方は 2 通り。どちらも正しい。

```
述語を名詞化する: このアプリの特徴は、誰でも簡単に画像が編集できることです。
主題を変える:     このアプリは、誰でも簡単に画像が編集できます。
```

レポートで同じ失敗が起きた例:

```
NG: 今回の整理としては、本質と事故を分けることで理解が進みました。
OK: 本質と事故を分けることで理解が進んだ。
```

長さが警告になる。主題と述語を同時に視野に入れられない長さの文を書いたら、他を確かめる前にまず切る。

## 3. 読点

用途は 4 つ、禁止はひとつ。

1. **節と句の切れ目に打つ** — 既定。構造を伝えるのはこの読点。
2. **直せない語順を救うために打つ** — 修飾の順序をどうしても直せないとき、どこで区切って読むかを示す。
3. **強調のために打つ** — 「私は、勉強ができるだけでも素晴らしいと思う。」は「私は」を対比として立てる。
4. **それ以上は打たない** — 境目すべてに打つと、読点が運んでいた信号が消える。

```
NG: 藤吉が、笑った、写真を、渡邉が、楽しそうに、撮っている、ところを、見て、山﨑は、嫉妬した。
OK: 藤吉が笑った写真を、渡邉が楽しそうに撮っているところを見て、山﨑は嫉妬した。
```

用途 2 と 3 は、**まず語順の修正を試し、直せなかったときだけ読点で救う**。読点で救った文は、たいてい語順でも直せる。

文中で項目を列挙するときは、読点ではなく中黒を使う。構造を示す読点と列挙が視覚的に区別できる。

```
NG: 最新のAI搭載アプリ、1TBのクラウドストレージ、デジタル保護機能を利用して、常に一歩先を行けます。
OK: 最新のAI搭載アプリ・1TBのクラウドストレージ・デジタル保護機能を利用して、常に一歩先を行けます。
```

レポートでは読点がすでに節構造を運んでいるので、区別しておく。

## 4. 文のレベルの習慣

**短く切って言い切る。** 長い複文は、それぞれが終わる複数の文になる。音読して息が続かないところには句点が足りない。

**敬体と常体を文書全体で統一する。** リサーチレポートの既定は常体（「〜である」「〜した」「〜ない」）。文末に「です」「ます」を使わない。依頼側から指定があったときだけ敬体にする。

**同じ語を一文のなかで繰り返さない。**

```
NG: 三分割で文章を書く方法は、小学校で文章を書くときから、企業の広告用の文章を書くときまで、幅広く使えます。
OK: 三分割で文章を書く方法は、小学校の作文から、企業の広告用の文章まで、幅広く使える。
```

**逆接の「が」は一文に一度まで。** 「〜ですが、〜が、〜である」は、どちらの「が」で論が折り返すのかを読者に考えさせる。文を分ける。

**代名詞を避ける。** 数節前のものを「それ」「これ」で受けると、読者は指示先を探しに戻る。名詞を繰り返すか、構造を変える。

**英語を直訳しない。** 「Yesです」は「そうです」でよい。`prose-style.md` 第 7 節が禁じている翻訳調の比喩と、出どころは同じである。

**読者が別の意味に取りうる語は、それが効く文で定義し直す。** 日常語と重なる術語（「複雑さ」「単純」「継続率」）は特に危ない。

## 5. 段落の頭に置く接続表現

関係が自明でない段落は、つながりの語で始める。日本語の候補:

| つながり方 | 段落頭に置く表現 |
|---|---|
| 順接・帰結 | したがって / そのため / この結果 |
| 逆接・対比 | 一方で / これに対して / ところが |
| 限定・留保 | ただし / とはいえ / この点については |
| 追加・並列 | さらに / 加えて / 同様に |
| 転換 | ここまでは〜だった。次に / 話題を変えると |
| 具体化 | 具体的には / たとえば |
| 言い換え | つまり / 言い換えると |

用途が同じ表現を連続する段落で繰り返さない。とくに「さらに」の連打は `prose-style.md` 第 6 節が埋め草として禁じている。関係が自明な段落には置かなくてよい。置くべきなのは、前の段落との関係が読まずにはわからない場合である。

## 6. 文の中に値を並べない

値の並びを地の文に置くと読めない。読者は比較相手が現れるまで各数値を保持させられる。

```
NG: 電池の耐久時間をテストした結果は、製品Aでは3時間、製品Bでは2.5時間、製品Cでは3.5時間でした。
OK: 表にする（製品 / 耐久時間）
```

散文は推論を運び、表は値を運ぶ。日本語では閾値がより低い。読点で区切った値の列が、節構造を示す読点と衝突するためである。

## 7. この出典が扱っていないこと
