# 検証プロンプト

作問した人とは別のコンテキスト（サブエージェント）で解かせる。渡すのは `passage`・`question`・`choices` だけ。`answer`・`choice_analysis`・`elimination_steps`・`theme`・`style` は渡さない。1 問につき 1 つのサブエージェントを使い、問題どうしで見せ合わない。

```text
あなたは中学受験国語の採点者です。次の問題を、本文だけを根拠に解いてください。

# 手順
1. 選択肢を2〜3のパーツに区切り、パーツごとに本文と照合する
2. 各選択肢を ○ / × で判定し、×の理由と、根拠になる本文の箇所（原文からの抜き出し、30字以内）を書く
3. 正解を1つ選ぶ。正解の根拠も本文から抜き出す
4. 次の問題点があれば flags に書く
   - multiple_answers: 正解と言える選択肢が2つ以上ある
   - no_evidence: ×の根拠を本文の箇所で示せない選択肢がある
   - interpretation: 感じ方・解釈の差でしか決められない
   - copy_answer: 正解が本文の語の丸写しになっている
   - fact_error: 説明文の事実に誤りがある

# 出力
JSONのみ。前置き・コードブロックは付けない。
{
  "answer": "ウ",
  "choice_analysis": {"ア": {"verdict": "×", "reason": "...", "evidence": "..."}, ...},
  "flags": []
}

# 問題
## 本文
<passage>

## 設問
<question>

## 選択肢
ア <choices.ア>
イ <choices.イ>
ウ <choices.ウ>
エ <choices.エ>
```

`<passage>` などは該当する値に置き換える。傍線部の `**` はそのまま渡してよい。

## 採否の基準

次の 3 つをすべて満たした問題だけを採用する。

1. 検証の `answer` が作問側の `answer` と一致する
2. 検証の `flags` が空である
3. 各誤答について、検証の `evidence` が指す本文の文が、作問側の `evidence` と同じ文である。指す文が違う誤答は、欠陥が複数ある可能性があるので、その選択肢を本文と読み合わせて確かめる。欠陥が割り当てた誤答タイプ（level 3 は最大 2 つ）に収まっていれば採用してよい。次の場合は文が違っても欠陥が複数あるとは見なさない
   - A（本文にない）: 「書いていない」ことの根拠は 1 文に決まらない。検証側が同じ点を「本文にない」と判定していればよい
   - D（部分ズレ）: 前半と後半のどちらを指していてもよい

不採用の問題は、本文か選択肢を直して、新しいサブエージェントで検証し直す。2 回直しても通らなければ捨てて、同じ割り当て（genre・level・question_type・answer_position）で新しく作る。
