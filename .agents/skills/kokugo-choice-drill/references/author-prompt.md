# 作問プロンプト

1 問ごとに、次の指示に従って作問する。入力（mode / genre / level など）は `workflow.md` の割り当てで決める。出力は 1 問分の JSON で、そのまま `qNN.json` の中身になる。

```text
あなたは中学受験国語（首都圏の上位校〜難関校レベル）の作問者です。
「消去法で解く力」を鍛えるための、短い文章の選択肢問題を1問作ります。
微妙に紛らわしい選択肢を含みますが、本文をていねいに読めば、解釈の差ではなく本文の根拠だけで正解が一つに決まる問題にします。

# 入力
mode: generate | excerpt
genre: 説明文 | 随筆 | 小説
theme: 題材（mode=generate のとき）
style: 文体の指定（人称・時制・視点。例「一人称・過去形」）
level: 1 | 2 | 3
question_type: 理由 | 気持ち | 気持ちの変化 | 内容合致 | 筆者の考え | 言い換え
wrong_types: 誤答タイプの指定（任意。例 ["B","D","G"]。未指定なら level に合わせて選ぶ）
answer_position: ア | イ | ウ | エ
excerpt: 本文（mode=excerpt のときのみ）
excerpt_source: 作品名・作者・底本（mode=excerpt のときのみ）

# mode ごとの本文の扱い
## mode=generate（完全自作）
- 字数: 説明文 150〜250字、随筆・小説 200〜300字
- 初見の文章にする。実在の作家の文体の模倣、有名作品の場面やあらすじの再現はしない。固有の場面と言い回しで書く
- 小学生が読める語彙にする
- 設問の根拠が本文の1〜3文で確認できるようにする。テーマと関係のない要素を増やさない
- 説明文:
  - 事実は一般に確かめられる内容に限る。数値・年代・固有名詞は、確実なもの以外は書かない
  - 「事実の説明」と「筆者の考え」を区別して書く。対比、逆接（しかし）、推量（〜ではないだろうか）、具体例から主張へ、のいずれかを入れる
- 随筆: 一人称で、体験から気づきへ進む。感情は行動や情景で示し、感情語の直接説明は多くて1つ
- 小説:
  - 出来事→心情→行動の因果が本文で追えるようにする
  - 傍線部の気持ちの直接のきっかけになる出来事と、そのときの行動・様子の描写を、本文に必ず入れる
  - 感情語の直接説明は多くて1つ。セリフと本音のずれを入れてよいが、ずれの根拠は本文に書く
- 傍線部は本文中の1か所に ** ** をつけて示す。気持ちを問うときは必ず付ける

## mode=excerpt（与えられた本文）
- 本文は一字も変更しない。傍線部の ** ** 以外は何も足さない
- この本文から、本文の根拠だけで一意に決まる設問が作れないときは、無理に作らず、unusable_reason に理由を書いて返す

# 選択肢の作り方
- 4択、正解は1つ。位置は answer_position に従う
- 誤答3つには、誤答タイプを1つずつ割り当てる（level 3 は1つの誤答に最大2つの欠陥まで）
- 各誤答の「×の根拠」は、本文の特定の箇所（原文の抜き出し）で指せるものにする。指せない誤答は作らない
- 微妙さは「程度・範囲・原因・語」のズレから作る。感じ方で分かれる差、本文から決められない差は作らない
- 正解は本文の語をそのまま使わず、言い換えて書く。誤答には本文の語をちりばめてよい
- 形式で解けないようにする
  - 4つの選択肢の長さの差は、最長が最短の1.3倍以内を目安にする。正解が最長・最短に偏らないようにする
  - 文末、文の構造をそろえる
  - 慎重な言い回し（〜ことが多い）が正解にだけ現れる形にしない
  - 断定語（すべて・必ず・だけ）の有無で正誤が決まる形にしない（正解に断定語が入る問題もある）
- 説明文では、筆者の意見と事実を混ぜた選択肢を、その混ざり方が誤りの原因になる場合にだけ使う

# 誤答タイプ
A 本文にない（付け足し・飛躍）
B 言い過ぎ（すべて・必ず・だけ・べき、推量を断定にする）
C 逆・因果のすり替え（主張と逆、原因と結果の入れ替え）
D 部分ズレ（前半○後半×、または逆）
E 事実だが問いに合わない（本文にあるが、聞かれていることの答えではない）
F 一般論・常識（筆者の主張ではなく世間の考え）
G 語のすり替え（似た語に差し替える。例: 納得→喜び）
H 方向ちがい（正反対、またはニュアンスのずれ）
I 表面読み（無言＝怒り、など行動・セリフの短絡的な解釈）
J 時間・場面のずれ（別の場面の気持ち）
K 主観の混入（自分ならこう、の読み込み）
L 程度のずれ（「少し」を「強く」にする）
M 原因のズレ（傍線部の直接のきっかけではない出来事と結びつける）

# 難易度
level 1: 誤答の多くが A・C で、本文1か所と照合すれば消える
level 2: D・B を混ぜる。2か所の照合が必要
level 3: G・L・M を使う。正解も言い換えで書き、一語単位で照合しないと決まらない

# 出力前の自己検証（すべて満たしたものだけ出力する。満たせなければ書き直す）
1. 各誤答について、×の根拠になる本文の箇所を原文から30字以内で抜き出せた
2. 正解について、根拠になる本文の箇所を1〜2か所、原文から抜き出せた
3. 正解が本文の語の丸写しになっていない
4. 各誤答の欠陥が、割り当てた誤答タイプと一致している
5. 本文を読めば、解釈の差ではなく本文の根拠で、正解が一つに決まる
6. 長さ・文末の偏りがなく、正解位置が指定どおりである
7. （generate のみ）事実に誤りがなく、既存の作品に似ていない
8. （気持ち問題のみ）傍線部の直接のきっかけと行動・様子の描写が本文にある

# 出力
JSONのみを出力する。前置き・後書き・コードブロックは付けない。
{
  "mode": "generate",
  "genre": "...",
  "level": 2,
  "question_type": "...",
  "theme": "題材（excerpt は場面の短い説明）",
  "style": "人称・時制・視点などの文体メモ",
  "passage": "本文（傍線部は ** ** で囲む）",
  "source": "自作 | 作品名・作者・底本",
  "question": "設問文",
  "choices": {"ア": "...", "イ": "...", "ウ": "...", "エ": "..."},
  "answer": "ウ",
  "choice_analysis": {
    "ア": {"verdict": "×", "error_type": "C", "defect": "何がどう誤りか（1文）", "evidence": "本文の抜き出し"},
    "イ": {"verdict": "×", "error_type": "A", "defect": "...", "evidence": "..."},
    "ウ": {"verdict": "○", "error_type": null, "defect": null, "evidence": ["本文の抜き出し1", "本文の抜き出し2"]},
    "エ": {"verdict": "×", "error_type": "G", "defect": "...", "evidence": "..."}
  },
  "elimination_steps": "どこに線を引くと、どの順で選択肢が消えるか（2〜3文）",
  "unusable_reason": null
}
```

## 保存形式との対応

- `unusable_reason` が null でない問題は保存しない。`unusable_reason` のキーも保存する JSON には入れない
- `evidence` は本文（`**` と空白を除いた形）の部分文字列にする。離れた 2 か所をつなぐときは `…` で区切る。チェックスクリプトが各片の一致を確かめる
- A（本文にない）の `evidence` は、その内容が書かれているはずの理由・事実を本文が実際に述べている箇所を指す。選択肢が本文の語や句をそのまま含む場合は、含まない言い方に直す（本文の一部が正しい選択肢は、A ではなく D になる）
- `defect` と `elimination_steps` は子どもが読む。サイトの答え合わせにそのまま表示される
