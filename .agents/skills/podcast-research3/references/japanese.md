# 日本語で書くときの作法

出力言語が日本語のときに読む。**必読**。

扱うのは文と語のレベルである。語の結びつき、修飾の距離、主述の対応、読点、語種のバランス。段落の運びと論証の順序は `prose-style.md` にある。

このファイルは二部構成になっている。第1部が**直訳調をやめる方法**、第2部が**日本語の文を整える方法**である。第1部を先に読む。リサーチレポートで読みにくさとして現れるのは、ほとんどが第1部の問題である。

---

# 第1部 直訳調をやめる

## 1.1 何が起きているか

英語の技術文書の言い回しを一語ずつ日本語に置き換えると、文法としては正しいのに、その分野の日本語として読んだことのない文ができる。読者は意味を取れるが、一拍余分にかかる。それが累積したものが「読みにくい」という感覚になる。

一文だけ見ると、たいてい「ちょっと変」で済む。レポート全体に百箇所あると、最後まで読めない文書になる。

```
NG: 各ラベルは完全な文を運ぶ。
OK: ラベルのあとは体言止めにせず、文の形にする。

NG: 辺が関係を運ぶ。
OK: 主張どうしの関係は、辺のラベルに書く。

NG: 付録は本文を短くするために稼ぐ。
OK: 付録があるから、本文を通読できる長さに収められる。

NG: 四つの規則がスロットを正直にする。
OK: この四つを守らないと、スロットが名前だけになる。
```

削った情報はない。英語の比喩を、日本語の技術文で使う言い方に置き換えただけである。

## 1.2 検出のしかた

**その動詞を、無生物主語のまま、同じ分野の日本語記事で見た記憶があるか。** 思い出せないなら直訳である。

第二の手がかりは、**元の英語が浮かぶかどうか**である。「〜を運ぶ」を見て carry が浮かぶなら、それは訳文である。自分で日本語として考えたなら英語は浮かばない。

第三に、**その語を辞書的な意味で受け取ったとき、絵が成立するか**を見る。「辺が関係を運ぶ」は、辺が荷物を持って移動する絵になる。成立しないなら比喩が移植できていない。

## 1.3 動詞の比喩 — 置き換え表

英語の技術文書で頻出する動詞の比喩である。左を書いたら止まる。

| 英語 | 直訳 | 日本語で書くなら |
|---|---|---|
| X carries Y | X は Y を運ぶ | X が Y を示す／X に Y を書く／X で Y が分かる |
| X earns its keep | X は稼ぐ | X を置く価値がある／X があるから〜できる |
| X buys you Y | X は Y を買う | X で Y が手に入る／X を使えば Y が省ける |
| buy back | 買い戻す | 取り戻す／別の層で用意する |
| make X honest | X を正直にする | X が形式だけにならないようにする |
| cosmetic | 化粧 | 見せかけ／名目だけ／形式だけ |
| surface area | 表面積 | 対象範囲／守る範囲／手を入れる箇所の数 |
| wearing the wrong hat | 帽子を間違えた | 置き場所を間違えた／層を間違えた |
| parallel threads | 並行する糸 | 同時に追う筋／並行する話題 |
| headings name things | 見出しは名付ける | 見出しは対象を指す |
| count your breath | 一息を数える | 一息で読める長さに収める |
| hold only what is true | 真であるものだけを持つ | 〜だけを扱う |
| X tells us | X は教えてくれる | X から〜が分かる／X は〜を示す |
| X knows Y | X は Y を知っている | X の出力は Y として一貫している |
| X allows Y | X は Y を許す | X があれば Y ができる |
| X sees Y | X は Y を見る | X で Y が起きる／X には Y が現れる |
| the question is open | 問いは開かれている | これは未解決である |
| X is promising | X は有望だ | X の何が使えるかを書く |
| earn a pass | 通過を稼ぐ | 合格の根拠にする |
| X is not yet done | X は尚未完 | X はまだ書き終わっていない |

表からのコピーではなく、型として使う。同じ構図の別の動詞が出てきたら、同じように置き換える。

## 1.4 名詞を動詞に戻す

英語は動詞を名詞にして弱い動詞で支える。日本語に直訳すると「〜の〜を行う」「〜化をもたらす」という重い文になる。日本語では動詞のまま書く。

```
NG: 取り込みステップの実装は、失敗行の削減をもたらした。
OK: 取り込みステップを実装して、失敗行が減った。

NG: ハッシュ契約の統一の実施が必要である。
OK: ハッシュの列順とNULL処理を揃える必要がある。

NG: レイヤ境界の明確化が品質事故の重大性を低下させる。
OK: 層の境界を決めておくと、品質事故が軽く済む。
```

危険な語尾は「〜化」「〜性」「〜の実施」「〜を行う」「〜をもたらす」である。連続したら名詞化を疑う。

ただし定着した術語は名詞のままでよい。「正規化」「冪等性」「可観測性」は、その分野がその形で使っている。置き換えるのは、書き手がその場で作った名詞である。

## 1.5 複合語を勝手に作らない

英語は名詞を並べるだけで複合語になる。日本語は助詞か、定着した熟語が必要である。

```
NG: 品質表面積が増える。
OK: 品質保証の対象が広がる。

NG: 人的キャパシティが上限を決める。
OK: モデリングできる人数が上限を決める。

NG: 人 × ソース × 履歴表面積 の不等式
OK: 人数とソース数と保守する履歴の量の釣り合い

NG: コスト関数の再最適化として提示されている。
OK: 損得を計算し直した結果として書かれている。
```

数式でないものを「不等式」「関数」と呼ばない。比喩として持ち込むと、読者はそこに数式があると思って探しに戻る。

## 1.6 「持つ」の乱用をやめる

英語の have / has をそのまま「持つ」にすると、日本語として不自然な箇所が大量に出る。

```
NG: このレポートは著者を持たない。
OK: このレポートは、書いた人の説明なしで読める。

NG: L1 は6スロット以外を持たない。
OK: L1 には、この6つ以外を入れない。

NG: 上限は数えられる形で持つ。
OK: 上限は数えられる形で決めておく。

NG: 各節は同じ四つの契約を持つ。
OK: どの節も次の四つを守る。
```

「持つ」が自然なのは、所有と所持、それに「意味を持つ」「責任を持つ」のような定着した言い方に限る。

## 1.7 無生物主語の扱い

日本語は無生物主語を取れるが、取れる動詞が英語より狭い。「示す」「表す」「決まる」「増える」なら自然で、「教える」「望む」「知る」「許す」は不自然になる。

仕組みを、意志や知識を持つものとして書かない。

```
NG: データが教えてくれるのは、欠測が集中していることである。
OK: 欠測は特定の期間に集中している。

NG: この規則は、読者に負荷をかけたがらない。
OK: この規則は、読者の負担を減らすために置いている。

NG: モデルはスタイルを知っている。
OK: モデルの出力は文体として一貫している。
```

無生物主語が続いて重くなったら、「〜によって」「〜では」「〜すると」に開く。

```
重い: 三層構造は、支える材料と辞典的な材料の区別を可能にする。
軽い: 三層に分けると、支える材料と辞典的な材料を区別できる。
```

## 1.8 定型の訳文を置き換える

| 訳文 | 日本語 |
|---|---|
| 読者が持ち帰るもの | 読んだあとに残る理解／この節で分かること |
| この節が〜へ足すのは | この節で〜がどう見えるようになるか |
| 〜という観点から／〜において | （多くは削れる。残すなら「〜では」「〜の場合」） |
| 〜に他ならない | （削る） |
| 重要なのは〜である | （削り、書く位置で示す） |
| 〜と言えるだろう | （根拠があれば言い切る。なければ何が未確認かを書く） |
| 概念の借用 | 考え方だけを取り入れること |
| 手法の去就 | その手法を続けるかどうか |
| 肩代わりしない | 代わりにはならない |
| 〜を可能にする | 〜できるようになる |
| 〜に寄与する | 〜の役に立つ／〜を支える |
| 本稿は〜を調査する / 三つの主張に整理する | （方法メタ。位置づけなら「ここでは〜を扱う。目的は〜だ」） |

## 1.9 スキル内部の語をレポートに出さない

このスキルは作業用の語彙を持っている。**「見取り図」「枠組み」「射程」「骨格」「スロット」「L1」「L2」「L3」「主張1」は、レポートの本文に出さない。** 読者はこのスキルを読んでいない。

```
NG: 枠組みは、三層の倉庫と二重の時間である。
OK: 運用上の失敗は、層の境界と時刻の二本の軸で分類できる。

NG: この節が見取り図へ足すのは、時間軸である。
OK: ここまでは「どこで正しさを固定するか」の話だった。以下は、固定したはずの境界が運用中に破られる形である。

NG: 読者が持ち帰る理解は次のとおりである。
OK: （そのまま内容を書く）

NG: このレポートの位置づけは次のとおりである。
OK: ここでは三代の定義を横断する。目的は「複雑さ」を取り違えない語彙を残すことだ。
```

見出しも同じである。`## 骨格` は内部語なので `## 全体像` にする。`## 概要` と `## 背景・歴史` は読者の語である。

# 第2部 日本語の文を整える

## 2.1 修飾語は係り先の近くに置く

日本語は修飾語を係り先からいくらでも離せる。離した分だけ、読者は係り先が現れるまでその修飾語を覚えておくことになる。読みにくい日本語のほとんどがこれである。覚えておくものが多すぎるか、覚えておく時間が長すぎる。

```
NG: 僕は山本が佐藤が受賞したと電話したのかと思った。
OK: 佐藤が受賞したと山本が電話したのかと僕は思った。
```

語はひとつも削っていない。入れ子をほどいて、次の修飾が始まる前に前の修飾が終わるようにしただけである。以下の規則はすべてここから出る。迷ったらここに戻る。

### 長い修飾語を前に

ひとつの係り先に修飾語が複数かかるときは、長いものを前に、短いものを後ろに置く。

```
OK: 十年前に読んだ古びた厚い本
NG: 厚い古びた十年前に読んだ本
```

短い修飾語を先頭に置くと、その後ろに続くすべてが、その修飾語と係り先の間に挟まる。

### 節を先に、句を後に

```
NG: Raw Vault は監査のために挿入のみで履歴を保持する層である。
OK: Raw Vault は、監査のために履歴を残す層であり、挿入のみで運用する。
```

### 主語を前に出すかどうか

主語を機械的に文頭へ出す規則は要らない。効くのは**主語と述語の距離が縮むとき**だけである。

```
NG: ソースの追加に対する耐性を得るために採用される Hub と Link の分離は、
    運用コストの大半を決める。
OK: Hub と Link を分けるのは、ソースの追加に強くするためであり、
    この設計が運用コストの大半を決める。
```

リサーチレポートに人称主語はほとんど出ないので、「私は」を反射で足す癖より、長い修飾を前に出す操作のほうが効く。

## 2.2 主述のねじれ

長い文は途中で主題を見失う。述語が文頭の主題と対応しないまま終わる。読者は違和感だけを覚えて、どこが変なのかは指摘できない。

見つけ方は、修飾語をすべて取り払って残りを読む。

```
NG:  このアプリの特徴は、誰でも簡単に画像が編集できます。
     → 特徴は、編集できます。    ← 「特徴」は「編集」できない
```

直し方は2通りある。どちらでもよい。

```
述語を名詞にする: このアプリの特徴は、誰でも簡単に画像を編集できることである。
主題を変える:     このアプリでは、誰でも簡単に画像を編集できる。
```

レポートで実際に出た形。

```
NG: 今回の整理としては、本質と事故を分けることで理解が進みました。
OK: 本質と事故を分けると、理解が進む。

NG: 運用記事の半分は、SQLよりもトレーニング計画と合意形成の失敗談である。
OK: 運用記事の半分は、SQLではなくトレーニング計画と合意形成の失敗を書いている。
```

長さが警告になる。主題と述語を同時に視野に入れられない長さの文を書いたら、他を確かめる前に切る。

## 2.3 「は」と「が」

節の第一文は主張である。その主張の**主題**を「は」で立てる。

```
弱い: Raw Vault を BI に直結しない運用が、公開事例で最も一貫して推される。
    ← 「が」で始めると、新情報の提示になり、主張として立たない
強い: Raw Vault は BI から直接読ませない。これが公開事例で最も一貫している境界である。
```

目安はこうである。すでに話題になっているもの、これから論じるものは「は」。初めて出すもの、その文で新しく特定するものは「が」。

対比を作るときは「は」を二つ並べる。

```
OK: Raw Vault は監査のため、情報マートは読みやすさのために存在する。
```

## 2.4 読点

用途は4つ、禁止がひとつ。

1. **節と句の切れ目に打つ** — これが既定。構造を伝える読点である。
2. **語順で直せないときに打つ** — どこで区切って読むかを示す。
3. **強調のために打つ** — 「私は、勉強ができるだけでも素晴らしいと思う。」は「私は」を対比として立てる。
4. **それ以上は打たない** — 境目すべてに打つと、読点の信号が消える。

```
NG: 藤吉が、笑った、写真を、渡邉が、楽しそうに、撮っている、ところを、見て、山﨑は、嫉妬した。
OK: 藤吉が笑った写真を、渡邉が楽しそうに撮っているところを見て、山﨑は嫉妬した。
```

用途2と3は、**まず語順を直してみて、直せなかったときだけ読点で救う**。読点で救った文は、たいてい語順でも直せる。

文中で項目を並べるときは、読点ではなく中黒を使う。構造を示す読点と、列挙を視覚的に区別できる。

```
NG: 列順、NULL処理、ソルトを揃えないと、JOIN が成立しなくなる。
OK: 列順・NULL処理・ソルトを揃えないと、JOIN が成立しなくなる。
```

## 2.5 語種のバランス

漢語だけで書くと硬くて速く読めない。和語だけだと締まらない。技術文書は、術語は漢語・カタカナのまま、それをつなぐ部分を和語にするのが読みやすい。

```
硬い: 層間境界の明確化は品質事故の重大性低減に寄与する。
自然: 層の境界を決めておくと、品質事故が軽く済む。

硬い: 当該手法の継続的運用には相当規模の人的資源投入が要求される。
自然: この手法を続けるには、それなりの人数が必要である。
```

漢語が三つ以上連続したら、ひとつを和語に開く。

カタカナ語は、その分野で定着しているものだけ使う。Hub・Link・Satellite・ハッシュ・パイプラインは定着している。「キャパシティ」「コミット」「ドライブする」は、それぞれ「余力」「引き受ける」「進める」で足りる。

## 2.6 文のレベルの習慣

**短く切って言い切る。** 長い複文は、それぞれが終わる複数の文になる。音読して息が続かない箇所には句点が足りない。ただし短ければ良いわけではない。ひとつの考えに条件が付いているだけの文は、120字あってもひと続きで読める。分けるべきなのは、独立した主張がふたつ入っている文である。

**常体で統一する。** 既定は「〜である」「〜した」「〜ない」。文末に「です」「ます」を使わない。指定があったときだけ敬体にする。

**同じ語を一文のなかで繰り返さない。**

```
NG: 三分割で文章を書く方法は、小学校で文章を書くときから、企業の広告用の文章を書くときまで、幅広く使える。
OK: 三分割で書く方法は、小学校の作文から企業の広告まで幅広く使える。
```

**逆接の「が」は一文に一度まで。** 「〜だが、〜が、〜である」は、どちらの「が」で論が折り返すのかを読者に考えさせる。文を分ける。

**代名詞を避ける。** 数節前のものを「それ」「これ」で受けると、読者は指示先を探して戻る。名詞を繰り返すか、構造を変える。

**「〜的」「〜性」を重ねない。** 「構造的な複雑性の本質的な特性」は何も言っていない。具体語に落とす。

**二重否定を避ける。** 「〜でないとは言えない」は「〜の可能性がある」と書く。

**受身を続けない。** 「〜されている」が三文続いたら、行為者を主語に戻せる文がある。

**体言止めは表と箇条書きだけ。** 散文では文にする。見出しは名詞句でよい。

**読者が別の意味に取りうる語は、それが効く文で定義し直す。** 日常語と重なる術語（「複雑さ」「単純」「品質」「継続率」）はとくに危ない。

## 2.7 段落の頭の接続表現

関係が自明でない段落は、つながりの語で始める。

| つながり方 | 段落頭に置く表現 |
|---|---|
| 順接・帰結 | したがって / そのため / この結果 |
| 逆接・対比 | 一方 / これに対して / ところが |
| 限定・留保 | ただし / とはいえ / この点は |
| 追加・並列 | さらに / 加えて / 同様に |
| 転換 | ここまでは〜だった。次に / 話題を変えると |
| 具体化 | 具体的には / たとえば |
| 言い換え | つまり / 言い換えると |

同じ表現を連続する段落で繰り返さない。とくに「さらに」の連打は `prose-style.md` 第7節が埋め草として挙げている。関係が自明な段落には置かなくてよい。

## 2.8 文中に値を並べない

値の並びを地の文に置くと読めない。読者は比較相手が出てくるまで各数値を覚えておくことになる。

```
NG: ハッシュの性能は、MD5 の CHAR(32) で TEMP が最大、RAW(16) で中程度、
    数値サロゲートで最小となる。
OK: 表にする（表現形式 / TEMP 使用量 / 出典）
```

散文は論を書き、表は値を並べる。日本語では、読点で区切った値の列が節構造を示す読点と衝突するため、表に移す閾値が英語より低い。

## 2.10 太字の使い方

日本語には大文字も語間の空白もない。斜め読みの手がかりは太字・リンク・数字・記号しかないので、**太字は装飾ではなく構造である**。個数の上限は設けない。代わりに、太字にするものを3種に限る。

1. 初出の術語
2. 数値と条件
3. 節末の持ち帰り一文のラベル

この3種以外に使わない。感想や強調のために太くしない。目安は本文1,000字あたり3〜8箇所で、それを下回ると灰色の帯になる。
